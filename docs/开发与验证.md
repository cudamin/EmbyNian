# 开发与验证

这一份是 2026-09-04 从 `README.md` 里拆出来的：README 改成面向使用者的功能介绍之后，架构、构建、发布和
自检这几段没有地方放。**规矩和禁忌的唯一出处仍然是 [`CLAUDE.md`](../CLAUDE.md)**，手上没做完的活在
[`PROGRESS.md`](../PROGRESS.md)；这里只管那两份之外的操作细节。

Core 与测试项目不引用 NuGet；WinUI 3 外壳按需引用 Windows App SDK 的子包（`Microsoft.WindowsAppSDK.Base`
等六个，不用那个把十个子包裹在一起的 `Microsoft.WindowsAppSDK` 总包），从 nuget.org 还原。

## 架构

解决方案是 `EmbyNian.sln`，三个项目：

- `src/EmbyNian.Core`：Emby 访问层、设置与凭据保险箱、mpv 配置读写，以及两个播放后端 —— 内置的 `LibMpvBackend` 和外部进程的 `MpvProcessBackend`。刻意不引用桌面 UI 与 `System.Drawing`，所以能在纯控制台里测。
- `src/EmbyNian.Shell`：当前 WinUI 3 外壳 —— 登录、主页、媒体库、搜索、详情页、设置、服务器管理、诊断与播放界面。
- `tests/EmbyNian.Tests`：手写的离线测试宿主，`dotnet run` 本身就是 runner，不用任何 NuGet 包。

第一代单项目源码（`MainForm.cs`、`MediaLibraryView.cs`、`ConfigEditorView.cs`、`UiTheme.cs`、`EmbyApiClient.cs` 等）曾经放在 `legacy/v1/` 供参考，2026-09-02 从工作树里删掉了：它不参与构建、也没有任何代码引用，而 git 历史里那一份是完整的（`git log -- legacy/v1` 找得到，`git show <提交>:legacy/v1/MainForm.cs` 读得出）。留在工作树里只会让人以为它还在这套东西里占着位置。

## 构建与运行

`global.json` 钉住了 SDK 版本。如果机器上装了多个 .NET SDK，`PATH` 里的 `dotnet` 不一定是那一个——
装了系统级 8.x 和用户级 10.x 的机器上，`PATH` 找到的是 8.x，然后每条命令都会以「找不到与 global.json
匹配的 SDK」失败。这种情况下把下面的 `dotnet` 换成那个装了 .NET 10 SDK 的完整路径，通常是
`$env:USERPROFILE\.dotnet\dotnet.exe`。（`tools\publish.ps1` 自己会挑，不用管。）

```powershell
dotnet build .\EmbyNian.sln -m:1
```

```powershell
dotnet run --project .\src\EmbyNian.Shell\EmbyNian.Shell.csproj
```

跑测试：

```powershell
dotnet run --project .\tests\EmbyNian.Tests\EmbyNian.Tests.csproj
```

**测试是「每次代码改动都跑」的那一道**（2026-09-21 起把最便宜的一道从发版里拆了出来：一整轮十秒出头、纯离线、
不碰服务器，见 CLAUDE.md 的四道闸门）。它里面带着一组**约定绊线**：`tests\EmbyNian.Tests\AgreementsTests.cs`
拿同目录的 `Agreements.txt` 那份基线比对今天的树 —— 内联字号与硬编码颜色只减不增、嵌套 `x:Bind` 路径只许减
（WUI2010 压制的前提）、UIA 句柄只许增、命令行开关表与分析器副本一字不差。它红了会把当前快照写到
`artifacts\code-review\agreements-actual.txt`，**逐行确认过再拷进基线**，不是反过来先改基线。

样式（`.editorconfig` 里行尾与空格那一半）是闸门 1 的第二条命令：

```powershell
dotnet format whitespace .\EmbyNian.sln --verify-no-changes --no-restore
```

`IDE0###` 那一族没接进来（2026-09-21 实测还剩下 163 条空格式与 7 条未用 using），所以它只查行尾、缩进、末尾空
行这几样。进这道门的当天它先红了：三个大文件的工作区副本是 CRLF、2660 行，而 git 因为 `.gitattributes` 归一化
不报它。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\refresh-analyzers.ps1          # 把技能里的分析器拷过来，打印新哈希
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\refresh-analyzers.ps1 -Check   # 只比不动：不一致退出码 1（发版前跑）
```

`tools\analyzers` 是技能里那两份的手工拷贝（`Directory.Build.props` 用 `Condition=Exists` 引它，少了它构建照样
通过、闸门 1 照样报「0 警告 0 错误」，所以它另由 `AgreementsTests` 的 `analyzer` 小节盯着哈希）。

发布发行版（自包含目录并打成 ZIP）：

```powershell
.\tools\publish.ps1
```

脚本默认发布 WinUI Shell 的 Windows App SDK 自包含版本到 `artifacts\publish\win-x64`，并生成
`artifacts\EmbyNian-0.0.1-win-x64.zip`。发布后会自动把着色器文件、mpv 依赖 dll 和
`libmpv-2.dll` 一起复制到输出目录，内置播放器不再依赖外部 mpv 安装。需要 MSIX 时可传
`-Msix`；脚本会在 Windows SDK 找到 `makeappx.exe` 时生成未签名的
`artifacts\EmbyNian-0.0.1-win-x64.msix`，否则明确报出安装 SDK 的提示。

改完代码只是要一个能跑的 exe 时传 `-NoArchive`：跳过打包那一步，同一次发布从一两分钟降到二十来秒
（把 296 MB 用 Optimal 压成一个 zip 就是那一两分钟）。上一次的 zip 照旧先删 —— 一个跟刚发布的目录对不上的
压缩包比没有压缩包更坏。交付前照旧不带这个开关：那个 zip 才是交出去的东西。

发布只需要仓库根目录的匹配版 `libmpv-2.dll`（117 MB，不入库）。**它要的其他东西全在仓库里**：着色器
文件在 `assets\shaders`（15 个文件 5.8 MB，2026-09-03 入库），libmpv 唯一那个不属于 Windows 的依赖
`vulkan-1.dll` 在 `assets\mpv-runtime`（2026-09-04 入库）。两样从前都是发布时从 `C:\mpv_config-2026.08.12`
现拷的 —— 那等于「这个程序能不能正确发布，取决于另一个软件还装没装」；现在那个目录一个字都不需要，
`-MpvRoot` 这个开关也跟着没了。csproj 用通配符把它们当普通内容文件拷进输出目录，所以**普通构建也带着
这两样**（从前只有发布才拷，`bin` 里跑起来自检会报每个着色器都缺）。有一条单测钉着「档位表点名的文件和
`assets\shaders` 里真有的一字不差」，两个方向分开报；`vulkan-1.dll` 由发布验证那一步盯着 —— 它是
libmpv 的静态导入，缺了连加载都失败，而四道闸门里没有一关会真的起播。每个文件的上游地址和许可写在
两个目录各自的 `README.md`。

默认 ZIP 是自包含的非打包 WinUI 3 应用：`--self-contained true` 和 `WindowsAppSDKSelfContained=true`
都是**发布脚本**给的（csproj 里那个属性默认是 `false`），所以目标机器不需要预装 .NET 10 Desktop Runtime
或 Windows App SDK。**WebView2 Runtime 只有「服务器控制台」那一页需要**，机器上没有它会被 catch 住、
那一页写一句话并留着「用浏览器打开」，其余功能不受影响。使用 `-FrameworkDependent` 时 ZIP 更小，
但目标机器需要预先安装 .NET 10 Desktop Runtime 和 Windows App SDK。MSIX 仍需用受信任证书签名后才能安装。

在自己这台机器上顺手放一个桌面快捷方式，传 `-Shortcut`；也可以单独跑：

```powershell
.\tools\shortcut.ps1
```

它写的是桌面上的 `EmbyNian.lnk`，指向 `artifacts\publish\win-x64\EmbyNian.exe`，图标取自 exe，
工作目录设成 exe 所在目录。`-Exe <路径>` 可以指向别的构建（比如调试输出），`-Remove` 删掉它。
发布默认不写桌面 —— 那是这台机器的事，不是构建的事。

## 隔离光标回归

`--probe-cursor` 在普通登录、单实例激活和用户设置加载之前进入独立数据目录，使用正式播放页及其 10Hz 计时器，不启动 Emby 播放或上报观看记录：

```powershell
.\artifacts\publish\win-x64\EmbyNian.exe --probe-cursor --screen 1
```

也可在同一页叠加绝对路径的本地视频，例如 `--probe-cursor C:\test\sample.mp4`。拒绝 URL、网络盘和重解析路径，并禁止视频引用外部文件或网络协议。单独使用，不与其他探针混用。

同族还有两条（同一套隔离方式：独立数据目录、不登录、不上报观看记录，都只认本地绝对路径，都单独使用）：`--probe-player-motion [<本地视频绝对路径>]` 逐帧量进场/退场/最大化/全屏的几何，`--probe-composition` 走合成交换链那一条路的独立诊断。**改播放管线时用它们，而不是拿真服务器试** —— 见 CLAUDE.md「播放相关改动的验证」那三档。

探针会暂时移动鼠标、创建窗口并切换全屏；结束时释放输入线程连接、恢复光标和原指针位置。它检查窗口化/全屏静止隐藏、持续十秒无可见光标、外来形状覆盖、真实移动恢复及退出清理。无法取得真实输入或指针被移出测试窗口时直接失败，不以内部状态冒充验收。结果在 `%LOCALAPPDATA%\EmbyNian\logs\cursor-probe-<时间>-<进程>\logs\cursor-probe.txt`。

## 自检与冒烟

`--self-check` 不显示窗口，逐个构建、布局并绘制每个页面、播放顶栏、音量竖条、跳过片头片尾按钮、播放统计面板与控制栏的每个浮层，同时检查着色器档位的文件是否还对得上、九十六格每一格是否还合规（放大器／后置锐化／降噪各不超过一个、每格都有色度重建、每个着色器的运行前置条件都落在选项里、链的次序和 mpv 的执行次序一致），并把「当前的视频渲染／图形接口／硬件解码能不能跑这套链」报成一行「信息」。除了「画出来不报错」，还有十几项专门盯行为和几何：「显隐规则」把指针依次摆到画面下沿、右边缘、正中间，再滚一次滚轮、静止 650 毫秒、停在进度条上，逐种情形核对该出现的浮层出现了、不该出现的没出现，「显隐规则已复位」接着确认一个控件都没留在屏上；「底边细线只在窗口化」验证浮层收起后窗口化留细进度线、全屏不留；「章节预览定位」拿一根 1138 像素宽的进度条在三处取预览，核对气泡不会越出画面、有缩略图时是画面（168 高）没有时只剩文字（45 高），并且浮层收起后它也跟着消失；「设置分类走查」把每张卡片逐个打开、数出全部行容器，「设置行模板」再从视觉树上数一遍必须一个不少 —— 那几套模板里任何一个坏掉的资源键都只表现为「那一行没了」，编译一声不响；「字幕字体列表」往字体搜索框里真打字，最关键的一条是搜一个任何机器上都不存在的名字之后，当前字体必须还留在列表里（能被过滤掉的值也能让这一行看起来没设置），顺带给四次全量过滤计时；「画面比例联动」核对 16:9 确实交给了窗口（客户区 1264×711 = 1.778）且归零能解除；「全屏几何」拉满 2560×1440 量覆盖、去边框、置顶和退出还原，「全屏时的任务栏」再问一句任务栏中点上盖着的是不是本窗口；「拖动标题栏移动窗口」按住标题栏走 37,23 像素，核对窗口跟着走、尺寸不变、松手后不再跟随、全屏时不接受拖动；「标题栏前进后退」把箭头的每种状态都摆一遍量位置（两头都走不动时两支都还站着、只是暗下来，面包屑那一行整行收起），核对整组箭头确实落在 32 像素高的标题栏里，再拿 `WM_NCHITTEST` 问窗口：两支箭头那块必须是客户区（否则按下去变成拖窗口），它两边和商标那块必须还答「标题栏」，而且在播放标题栏来回切过一轮之后依然如此 —— 撤回一次分区声明（`ClearRegionRects` 或空数组）会让整条带子永久变成客户区，看完一部片回来就拖不动窗口了；「系统按钮点得动」把框架自己报的右侧留白等分三格，逐格问 `WM_NCHITTEST`，必须分别答最小化、最大化、关闭按钮 —— 在这条带子上声明区域会盖掉框架给那三颗按钮报的位置，按钮照画照高亮、却只剩一张图，「播放时右上角归页面」再反过来问同一三格，播放时必须都答客户区，因为那时候画在那儿的是浮层自己的窗口按钮；「卡片悬浮按钮」把首页真卡片上的悬浮层亮起来量一遍：可播放卡片的圆形播放键中心必须压在封面中心上（差一个逻辑像素都算，截图上看「差不多在中间」是看不出来的），媒体库卡片必须一个已观看/收藏都没有、只剩「更多」；最后两条要连着真服务器才问得出来，它们各自证的那句话没有任何本地夹具能替代 ——「跨季相邻单集」在服务器上挑一部真的多季剧，用整部剧的单集列表找出一个季边界，断言从季末走一步正好落在下一季第一集、退回来又是原来那一集，再把交给「选集」的那一季列表跟服务端单独按季返回的列表逐个 id 比一遍（跨得过去靠的是服务端 `ParentIndexNumber,IndexNumber,SortName` 这个顺序，不是本地算集号），「详情页季切换」另建一个不上屏的详情页视图模型换一季，断言卡片、标题和播放目标都跟着走 —— 标题要单独断言，因为它来自 `EpisodeScope` 而不是来自卡片，集子对了、季名错了的页面否则会混过去；这两条遇上没登录、这台服务器上没有可走的季边界或往返出错时报「信息」而不是失败。报告写在
`%LOCALAPPDATA%\EmbyNian\logs\selfcheck-shell.txt`，全部通过返回 0，有问题返回 1。

```powershell
.\EmbyNian.exe --self-check
```

加上 `--dump-ui` 会多写两份东西到 `%LOCALAPPDATA%\EmbyNian\logs`：`selfcheck-shell.png` 是自检走完最后

tag，图片仓库只会去取有 tag 的图，所以那一关里虚化背景和卡片剧照仍然是占位图。

### 逐行比报告：每次都会变的行

**有十项每次运行都不一样，是设计如此**：时间戳、两个 `hwnd`、字体过滤用了多少毫秒、光标形状句柄和线程号、
能不能把指针挪到画面中心、静止那一段量出来是 2000 还是 2015 毫秒、任务栏等了多少毫秒、亚克力背后那个取样
颜色、主页轮播那一行的服务器读数，加上诊断页那两行的日志条数。**逐行比两份报告时先照这份名单划掉，只有这
十项变了不算回归；剩下的才值得查。**

**但逐行比已经是例外流程了**（2026-09-21 起）：闸门 4 跑的是 `tools\selfcheck-diff.ps1`，它只比「哪些检查跑
了、各答了什么」，详情里的数字（上面这十项全在里面）天然不参与比对，所以这份名单不必每次人肉划掉；窗口最大
化时那三行必红的事它也在内部处理掉——它临时把 `settings.json` 里的 `WindowMaximized` 按非最大化跑一次，跑完
原样还原，不再需要手动改两次。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\selfcheck-diff.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\selfcheck-diff.ps1 -Log .\log.txt   # 只比一份已有日志，不启动程序
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\selfcheck-diff.ps1 -UpdateBaseline  # 确认过了再把当前结果认成基线
```

绿＝本次没有 `[失败]`、没有检查消失、没有「通过 → 信息」的降级；红会把每一条连同详情打出来（长的截到 220
字，日志本身不动）。基线是 [`selfcheck-baseline.txt`](selfcheck-baseline.txt)：只有「状态 + 检查名」，同名多行
的检查（设置卡片）在那里只有一份 —— 逐卡的行数由那一行自己的读数盯着；失败的行不写进基线，因为**有失败就是
红的，与基线无关**。人肉逐行只剩一种场合：脚本还没跑通、要看原始日志的时候。

名单会跟着新增的检查漂移，**改了就改这里**。它从前写在按月滚的进度归档里（`docs/progress-2026-09.md`，
2026-09-02 那一轮定的十项），而归档一到下个月就换文件，任何指过去的路都自带保质期 —— 归档里那一份是当时
的原文，不再是现行名单。

`--theme <id>` 让这一次运行换一套主题（`--theme midnight`，也接受 `--theme=midnight`），认不出来的 id
回落到默认那套。**它只改这一次运行看到的颜色，不写设置文件** —— 五套配色里换主题的唯一入口是设置页上点一
块色板，所以除了默认那套，别的一张照片都拍不到。配合 `tools\shot.ps1` 就是一条命令一张照片：

```powershell
.\tools\shot.ps1 -Exe artifacts\publish\win-x64\EmbyNian.exe -Out shots\midnight.png -ExeArgs "--theme midnight --show-settings" -WindowTitle 设置
```

**这个开关从前还有一份更要紧的用处，现在没有了**：`--theme daylight` 拍一张，是「浅色主题下才会露出来的毛病」
（没登记进 `ThemeHost` 的画刷、系统自己画的那块标题栏）唯一的照法。**「晴昼」2026-09-05 按用户一句「删掉晴昼
主题」删掉了**，五套主题从此全是深色 —— 那类毛病也就没有东西逮得住了。别再照旧文档去跑 `--theme daylight`，
它只会回落到默认那套；要重新有这面照妖镜，把那一套加回 `UiThemes` 即可（怎么加见那个文件的类注释）。

## 数据与路径

数据目录是 `%LOCALAPPDATA%\EmbyNian`：

- `settings.json` 与 `settings.backup.json`；文件损坏时会被隔离并回退到默认设置，读取永不抛异常
- `logs\app-yyyyMMdd.log` 运行日志，界面里的「诊断」页看的是同一份内容（内存里保留最近 500 条）
- `cache\images` 海报与缩略图缓存
- `screenshots` 播放中截的图
- `webview2` 「服务器控制台」那一页的浏览器配置目录，只有真打开过控制台才建

首次启动在登录页填写 Emby 地址、用户名和密码；外部 mpv 可执行文件路径在「设置 → 播放器」里改。内置后端使用程序随附的 `libmpv-2.dll`、着色器目录和依赖 dll。两个后端都不读 `mpv.conf` / `input.conf`。
