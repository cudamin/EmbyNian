# 开发与验证

本文保存操作细节；当前规则见 [CLAUDE.md](../CLAUDE.md)，在途工作与历史记录见 [PROGRESS.md](../PROGRESS.md)。规则的执行条件与授权边界不在这里另立副本。

Core 与测试项目目前不引用 NuGet，保持轻量与离线可测；这不是测试框架的限制。Shell 按需引用 Windows App SDK 子包以控制载荷，具体选择和版本以项目文件为准。

## 架构

解决方案是 `EmbyNian.sln`，三个项目：

- `src/EmbyNian.Core`：Emby 访问层、设置与凭据保险箱、mpv 配置读写，以及两个播放后端 —— 内置的 `LibMpvBackend` 和外部进程的 `MpvProcessBackend`。刻意不引用桌面 UI 与 `System.Drawing`，所以能在纯控制台里测。
- `src/EmbyNian.Shell`：当前 WinUI 3 外壳 —— 登录、主页、媒体库、搜索、详情页、设置、服务器管理、诊断与播放界面。
- `tests/EmbyNian.Tests`：手写的离线测试宿主，`dotnet run` 本身就是 runner，不用任何 NuGet 包。

第一代单项目源码（`MainForm.cs`、`MediaLibraryView.cs`、`ConfigEditorView.cs`、`UiTheme.cs`、`EmbyApiClient.cs` 等）曾经放在 `legacy/v1/` 供参考，2026-09-02 从工作树里删掉了：它不参与构建、也没有任何代码引用，而 git 历史里那一份是完整的（`git log -- legacy/v1` 找得到，`git show <提交>:legacy/v1/MainForm.cs` 读得出）。留在工作树里只会让人以为它还在这套东西里占着位置。

## 构建与运行

**构建、还原、测试与发版的命令及触发条件统一见 [CLAUDE.md「四道闸门与日常交付」](../CLAUDE.md#四道闸门与日常交付)。** 在当前工作树根目录运行，使用满足 `global.json` 的用户级 SDK。不要从独立工作树跳回固定主目录，也不要用 PATH 上的旧 SDK。

测试要先编译当前 Release 测试程序及 Core，再用 `--no-build` 运行；完整方案已成功编译当前代码时可复用那份输出。构建失败就停止，发布应用不能替代编译测试。

中间迭代需要看界面时，先按主规则构建当前 Shell，再运行这份开发输出；不要让 `dotnet run` 隐式另起一轮没有单节点约束的构建：

```bash
"$HOME/.dotnet/dotnet.exe" run --project ./src/EmbyNian.Shell/EmbyNian.Shell.csproj -c Release --no-build
```

这不是最终交付，桌面快捷方式仍指向发布目录。启动普通应用可能恢复已保存的登录；验证播放仍遵守主规则的三档边界。

### 约定基线

`tests/EmbyNian.Tests/AgreementsTests.cs` 对照同目录 `Agreements.txt` 检查当前树：内联字号和颜色的数量、嵌套绑定路径、已有自动化句柄、命令行开关以及分析器哈希。具体策略与例外在 CLAUDE.md。检查会写出 `artifacts/code-review/agreements-actual.txt`；先复核实际改动及其使用者，再更新相关基线行，不能整份覆盖来消除失败。

空白检查并不等于全部代码风格通过，也不覆盖所有脚本文件；其命令和覆盖边界见主规则。

### 分析器维护

`tools/analyzers` 的载荷随仓库入库，发版使用这份确定的载荷，完整性由约定测试的哈希检查守卫。`Directory.Build.props` 的 `Condition=Exists` 会让缺载荷的构建继续，所以不能只看构建的警告数。

下列命令只比较本机插件候选与仓库副本，供安排独立升级使用，不是发版必过项：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/refresh-analyzers.ps1 -Check
```

默认候选按插件文件的写时间选取，不保证是语义版本最新。找不到候选时脚本会说明跳过并返回 0；这个 0 不证明分析器存在或有效。明确选择来源后，升级载荷的命令为：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/refresh-analyzers.ps1
```

需要指定来源时传 `-SkillRoot <分析器目录>`；复核新诊断、文件与哈希，再更新基线并按主规则完整验证。不要为匹配某台机器的旧插件而降级仓库载荷。

## 发布与交付

需要自包含目录和 ZIP 时运行：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/publish.ps1
```

脚本默认把当前工作树的 Shell 发布到 `artifacts/publish/win-x64`，ZIP 文件名中的版本来自 `Directory.Build.props`。原生库、着色器和其他载荷由项目复制，随后运行 `verify-publish.ps1` 检查完整性。需要 MSIX 时传 `-Msix`；具体打包、签名参数以发布脚本为准，不在这里维护第二份工具链说明。

只刷新本机可运行目录时按 CLAUDE.md 使用 `-NoArchive`，需要分发压缩包时才生成 ZIP。独立工作树里的默认发布不会更新主目录产物或已有快捷方式，最终由交付会话在整合并验证后刷新实际交付目录。没有刷新时明确说明，不能用另一个目录发布成功代替。

每棵需要发布的工作树都要有匹配的根目录 `libmpv-2.dll`（不入库）。着色器在 `assets/shaders`，原生依赖在 `assets/mpv-runtime`；上游和许可见各目录 README。普通构建也复制这些项目载荷。着色器文件与档位表的对应关系由测试检查，原生依赖与发布完整性由发布验证检查；这些检查不等于实际播放通过。

默认 ZIP 是自包含的非打包 WinUI 3 应用：`--self-contained true` 和 `WindowsAppSDKSelfContained=true`
都是**发布脚本**给的（csproj 里那个属性默认是 `false`），所以目标机器不需要预装 .NET 10 Desktop Runtime
或 Windows App SDK。**WebView2 Runtime 只有「服务器控制台」那一页需要**，机器上没有它会被 catch 住、
那一页写一句话并留着「用浏览器打开」，其余功能不受影响。使用 `-FrameworkDependent` 时 ZIP 更小，
但目标机器需要预先安装 .NET 10 Desktop Runtime 和 Windows App SDK。MSIX 仍需用受信任证书签名后才能安装。

在自己这台机器上顺手放一个桌面快捷方式，传 `-Shortcut`；也可以单独跑：

```powershell
.\tools\shortcut.ps1
```

它写的是桌面上的 `EmbyNian.lnk`，指向 `artifacts\publish\win-x64\EmbyNian.exe`，图标取自 exe，
工作目录设成 exe 所在目录。`-Exe <路径>` 可以指向别的构建（比如调试输出），`-Remove` 删掉它。
发布默认不写桌面 —— 那是这台机器的事，不是构建的事。

## 隔离光标回归

`--probe-cursor` 在普通登录、单实例激活和用户设置加载之前进入独立数据目录，使用正式播放页及其 10Hz 计时器，不启动 Emby 播放或上报观看记录：

```powershell
.\artifacts\publish\win-x64\EmbyNian.exe --probe-cursor --screen 1
```

也可在同一页叠加绝对路径的本地视频，例如 `--probe-cursor C:\test\sample.mp4`。拒绝 URL、网络盘和重解析路径，并禁止视频引用外部文件或网络协议。单独使用，不与其他探针混用。

同族还有 `--probe-player-motion [<本地视频绝对路径>]`，逐帧量进场/退场/最大化/全屏几何，以及 `--probe-composition [<本地视频绝对路径>]`，独立诊断合成交换链。它们单独运行，使用隔离数据目录，不登录、不上报；提供的视频路径必须通过本地文件校验。**三条目前都固定使用集成管线，不覆盖独占窗口、uosc 或独占同窗换片。** 运行通过只证明实际执行的路径；独占改动的验证缺口与新增离线入口要求见 CLAUDE.md 的播放验证规则。

探针会暂时移动鼠标、创建窗口并切换全屏；结束时释放输入线程连接、恢复光标和原指针位置。它检查窗口化/全屏静止隐藏、持续十秒无可见光标、外来形状覆盖、真实移动恢复及退出清理。无法取得真实输入或指针被移出测试窗口时直接失败，不以内部状态冒充验收。结果在 `%LOCALAPPDATA%\EmbyNian\logs\cursor-probe-<时间>-<进程>\logs\cursor-probe.txt`。

## 隔离缩放像素回归

`--probe-player-motion` 的缩放检查使用固定的红、绿、黄、蓝、品红、青六条等宽彩条，运动区只放在顶部，避免运动图案遮住取色点。普通影片不满足这个像素判据；可在工作树根目录用 FFmpeg 生成本地素材（已有同名文件时命令拒绝覆盖）：

```bash
ffmpeg -hide_banner -loglevel error -f lavfi -i "color=c=red:s=1280x720:r=30:d=45" -f lavfi -i "testsrc2=s=1280x72:r=30:d=45" -filter_complex "[0:v]drawbox=x=214:y=0:w=213:h=720:color=lime:t=fill,drawbox=x=427:y=0:w=213:h=720:color=yellow:t=fill,drawbox=x=640:y=0:w=213:h=720:color=blue:t=fill,drawbox=x=853:y=0:w=213:h=720:color=magenta:t=fill,drawbox=x=1066:y=0:w=214:h=720:color=cyan:t=fill[bars];[bars][1:v]overlay=x=0:y=0:shortest=1[out]" -map '[out]' -an -c:v libx264 -preset fast -crf 18 -pix_fmt yuv420p -n work/resize-bars-fixture.mp4
```

```bash
ffmpeg -hide_banner -loglevel error -i work/resize-bars-fixture.mp4 -frames:v 1 -n work/resize-bars-fixture.png
```

```bash
./artifacts/publish/win-x64/EmbyNian.exe --probe-player-motion "$(pwd -W)/work/resize-bars-fixture.mp4" --screen 2
```

单显示器改用 `--screen 1`。探针发送原生拖边消息，走正式宽高比约束，不移动真实鼠标；像素检查期间暂时将隔离窗口置顶，结束后恢复。断言包括拖动中缓冲稳定、视频仍推进、松手后最终尺寸生效及保留帧收回、收尾被再次拖动打断时不串状态、播放与暂停时大幅缩放的彩条完整。屏幕像素一次抓入内存后取点，不用多次 `GetPixel` 跨帧拼读数；窗口被遮挡或移到屏外时报错，不把别的窗口当作视频。

快速反向拖边不逐拍等待截图，仍需配外部连续屏幕捕获检查中间帧。报告在 `%LOCALAPPDATA%\EmbyNian\logs\player-motion-probe-<时间>-<进程>\logs\player-motion-probe.txt`。报告内的非阻断诊断单独阅读，不能把进程退出码为 0 当成每项诊断都通过。

## 自检与冒烟

`--self-check` 会使用诊断窗口，默认屏幕与执行条件见 CLAUDE.md；它逐个构建、布局并绘制每个页面、播放顶栏、音量竖条、跳过片头片尾按钮、播放统计面板与控制栏的每个浮层，同时检查着色器档位的文件是否还对得上、九十六格每一格是否还合规（放大器／后置锐化／降噪各不超过一个、每格都有色度重建、每个着色器的运行前置条件都落在选项里、链的次序和 mpv 的执行次序一致），并把「当前的视频渲染／图形接口／硬件解码能不能跑这套链」报成一行「信息」。除了「画出来不报错」，还有十几项专门盯行为和几何：「显隐规则」把指针依次摆到画面下沿、右边缘、正中间，再滚一次滚轮、静止 650 毫秒、停在进度条上，逐种情形核对该出现的浮层出现了、不该出现的没出现，「显隐规则已复位」接着确认一个控件都没留在屏上；「底边细线只在窗口化」验证浮层收起后窗口化留细进度线、全屏不留；「章节预览定位」拿一根 1138 像素宽的进度条在三处取预览，核对气泡不会越出画面、有缩略图时是画面（168 高）没有时只剩文字（45 高），并且浮层收起后它也跟着消失；「设置分类走查」把每张卡片逐个打开、数出全部行容器，「设置行模板」再从视觉树上数一遍必须一个不少 —— 那几套模板里任何一个坏掉的资源键都只表现为「那一行没了」，编译一声不响；「字幕字体列表」往字体搜索框里真打字，最关键的一条是搜一个任何机器上都不存在的名字之后，当前字体必须还留在列表里（能被过滤掉的值也能让这一行看起来没设置），顺带给四次全量过滤计时；「画面比例联动」核对 16:9 确实交给了窗口（客户区 1264×711 = 1.778）且归零能解除；「全屏几何」拉满 2560×1440 量覆盖、去边框、置顶和退出还原，「全屏时的任务栏」再问一句任务栏中点上盖着的是不是本窗口；「拖动标题栏移动窗口」按住标题栏走 37,23 像素，核对窗口跟着走、尺寸不变、松手后不再跟随、全屏时不接受拖动；「标题栏前进后退」把箭头的每种状态都摆一遍量位置（两头都走不动时两支都还站着、只是暗下来，面包屑那一行整行收起），核对整组箭头确实落在 32 像素高的标题栏里，再拿 `WM_NCHITTEST` 问窗口：两支箭头那块必须是客户区（否则按下去变成拖窗口），它两边和商标那块必须还答「标题栏」，而且在播放标题栏来回切过一轮之后依然如此 —— 撤回一次分区声明（`ClearRegionRects` 或空数组）会让整条带子永久变成客户区，看完一部片回来就拖不动窗口了；「系统按钮点得动」把框架自己报的右侧留白等分三格，逐格问 `WM_NCHITTEST`，必须分别答最小化、最大化、关闭按钮 —— 在这条带子上声明区域会盖掉框架给那三颗按钮报的位置，按钮照画照高亮、却只剩一张图，「播放时右上角归页面」再反过来问同一三格，播放时必须都答客户区，因为那时候画在那儿的是浮层自己的窗口按钮；「卡片悬浮按钮」把首页真卡片上的悬浮层亮起来量一遍：可播放卡片的圆形播放键中心必须压在封面中心上（差一个逻辑像素都算，截图上看「差不多在中间」是看不出来的），媒体库卡片必须一个已观看/收藏都没有、只剩「更多」；最后两条要连着真服务器才问得出来，它们各自证的那句话没有任何本地夹具能替代 ——「跨季相邻单集」在服务器上挑一部真的多季剧，用整部剧的单集列表找出一个季边界，断言从季末走一步正好落在下一季第一集、退回来又是原来那一集，再把交给「选集」的那一季列表跟服务端单独按季返回的列表逐个 id 比一遍（跨得过去靠的是服务端 `ParentIndexNumber,IndexNumber,SortName` 这个顺序，不是本地算集号），「详情页季切换」另建一个不上屏的详情页视图模型换一季，断言卡片、标题和播放目标都跟着走 —— 标题要单独断言，因为它来自 `EpisodeScope` 而不是来自卡片，集子对了、季名错了的页面否则会混过去；这两条遇上没登录、这台服务器上没有可走的季边界或往返出错时报「信息」而不是失败。报告写在
`%LOCALAPPDATA%\EmbyNian\logs\selfcheck-shell.txt`，全部通过返回 0，有问题返回 1。

### 逐行比报告：每次都会变的行

**有十项每次运行都不一样，是设计如此**：时间戳、两个 `hwnd`、字体过滤用了多少毫秒、光标形状句柄和线程号、
能不能把指针挪到画面中心、静止那一段量出来是 2000 还是 2015 毫秒、任务栏等了多少毫秒、亚克力背后那个取样
颜色、主页轮播那一行的服务器读数，加上诊断页那两行的日志条数。**逐行比两份报告时先照这份名单划掉，只有这
十项变了不算回归；剩下的才值得查。**

**但逐行比已经是例外流程了**（2026-09-21 起）：闸门 4 跑的是 `tools\selfcheck-diff.ps1`，它只比「哪些检查跑
了、各答了什么」，详情里的数字（上面这十项全在里面）天然不参与比对，所以这份名单不必每次人肉划掉；窗口最大
化时那三行必红的事它也在内部处理掉——它临时把 `settings.json` 里的 `WindowMaximized` 按非最大化跑一次，跑完
原样还原，不再需要手动改两次。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\selfcheck-diff.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\selfcheck-diff.ps1 -Log .\log.txt   # 只比一份已有日志，不启动程序
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\selfcheck-diff.ps1 -UpdateBaseline  # 确认过了再把当前结果认成基线
```

绿＝本次没有 `[失败]`、没有检查消失、没有「通过 → 信息」的降级；红会把每一条连同详情打出来（长的截到 220
字，日志本身不动）。基线是 [`selfcheck-baseline.txt`](selfcheck-baseline.txt)：只有「状态 + 检查名」，同名多行
的检查（设置卡片）在那里只有一份 —— 逐卡的行数由那一行自己的读数盯着；失败的行不写进基线，因为**有失败就是
红的，与基线无关**。人肉逐行只剩一种场合：脚本还没跑通、要看原始日志的时候。

名单会跟着新增的检查漂移，**改了就改这里**。它从前写在按月滚的进度归档里（`docs/progress-2026-09.md`，

## 数据与路径

数据目录是 `%LOCALAPPDATA%\EmbyNian`：

- `settings.json` 与 `settings.backup.json`；文件损坏时会被隔离并回退到默认设置，读取永不抛异常
- `logs\app-yyyyMMdd.log` 运行日志，界面里的「诊断」页看的是同一份内容（内存里保留最近 500 条）
- `cache\images` 海报与缩略图缓存
- `screenshots` 播放中截的图
- `webview2` 「服务器控制台」那一页的浏览器配置目录，只有真打开过控制台才建

首次启动在登录页填写 Emby 地址、用户名和密码；外部 mpv 可执行文件路径在「设置 → 播放器」里改。内置后端使用程序随附的 `libmpv-2.dll`、着色器目录和依赖 dll。两个后端都不读 `mpv.conf` / `input.conf`。
