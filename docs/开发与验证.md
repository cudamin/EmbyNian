# 开发与验证

本文保存命令、操作方法和有适用条件的排障经验；当前规则与验证触发条件见 [CLAUDE.md](../CLAUDE.md)，在途工作及历史证据见 [PROGRESS.md](../PROGRESS.md)。版本、参数和检查能力以源码与脚本为准，不在这里另立授权或验收标准。

## 架构

MoviePilot 主页订阅分区、订阅管理、入库统计与播放入口见 [MoviePilot订阅](MoviePilot订阅.md)。`--probe-shell` 包含三个订阅检查，播放按钮仅交给捕获目标的假动作，不实际播放媒体。

解决方案为 `Momoka.sln`：

- `src/Momoka.Core`：Emby 访问、设置与凭据保险箱、mpv 配置，以及内置 `LibMpvBackend` 和外部 `MpvProcessBackend`。不引用桌面 UI；当前无 NuGet 依赖，这是轻量选择，不是测试框架限制。
- `src/Momoka.Shell`：WinUI 外壳，Windows App SDK 按需引用子包，具体版本以 csproj 为准。
- `tests/Momoka.Tests`：当前只引用 Core 的离线控制台测试宿主，`dotnet run` 是 runner。

旧 WinForms 外壳已退出工作树；需要查迁移历史时用 Git 历史，不恢复旧目录作为新增实现模板。架构与专项操作见 `.claude/skills/`。

## 构建与运行

### 标准命令

在**当前工作树根目录**运行。使用 `$HOME/.dotnet/dotnet.exe`，先按 `global.json` 核实 SDK；不要跳回另一棵树，也不要让 IDE 或 `dotnet run` 隐式触发不同参数的构建。各类任务需要哪些闸门、如何判定交付，统一见 [主规则](../CLAUDE.md#四道闸门与日常交付)。

新工作树缺少还原结果或包版本变化时先还原：

```bash
"$HOME/.dotnet/dotnet.exe" restore ./Momoka.sln --disable-parallel -m:1 -p:BuildInParallel=false
```

**闸门 1：完整构建与空白检查。**

```bash
"$HOME/.dotnet/dotnet.exe" build ./Momoka.sln -c Release --no-restore -m:1 -p:BuildInParallel=false -p:UseSharedCompilation=false -p:MSBuildNodeReuse=false
```

```bash
"$HOME/.dotnet/dotnet.exe" format whitespace ./Momoka.sln --verify-no-changes --no-restore
```

`format whitespace` 不检查所有脚本的编码和语法；改 PowerShell 脚本或完整验收时另外运行：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-scripts.ps1
```

该脚本检查当前工作树受版本控制及未忽略的新 `.ps1`：UTF-8 BOM、LF、末尾换行和 PowerShell 语法。它不执行脚本，不证明脚本的运行行为正确；`-Path <文件>` 可检查指定文件。

维护脚本的离线回归使用隔离夹具，不启动产品、不发布到实际交付目录，也不改仓库的分析器载荷：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/test-maintenance.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools/test-shader-publish.ps1
```

自检比较器另有 `tools/test-selfcheck-diff.ps1`：先验证完整/缺失/重复/失败日志与基线变更，再用脚本现场编译的临时 `Fixture.exe` 验证进程退出码、隔离回执和运行目录。它不启动 Momoka、不读取真实设置，但**离线不等于没有系统确认弹窗**。临时程序未签名，Windows 可能要求确认运行；无人值守时不能保证整组完成。遇到提示或取消时保留日志，报告未完成的进程覆盖，不通过关闭安全检查、解除阻止或换启动方式取得「通过」。只读比较已有日志用 `selfcheck-diff.ps1 -Log`，它不替代进程路径回归。
着色器发布夹具逐个移除 GLSL、HOOK 与许可文件，并注入损坏和多余文件；只改本树 `artifacts/shader-publish-tests` 的临时载荷，不启动播放器。发布校验对文件集合及 SHA-256 逐项核对，不再以“至少一个 GLSL”当完整。

**闸门 2：先编译当前测试，再运行。** 没有可复用的当前完整构建时先执行：

```bash
"$HOME/.dotnet/dotnet.exe" build ./tests/Momoka.Tests/Momoka.Tests.csproj -c Release --no-restore -m:1 -p:BuildInParallel=false -p:UseSharedCompilation=false -p:MSBuildNodeReuse=false
```

前一步成功后执行：

```bash
"$HOME/.dotnet/dotnet.exe" run --project ./tests/Momoka.Tests/Momoka.Tests.csproj -c Release --no-build
```

`-c Release` 只能选输出目录，不能证明输出是新的；发布 Shell 也不会刷新测试程序集。

**闸门 3：刷新实际交付目录。**

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/publish.ps1 -NoArchive
```

**闸门 4：自检及基线比较。**

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/selfcheck-diff.ps1
```

自检会操作窗口，并可能使用保存的账号读库，不是离线测试。报告位置与隔离机制见下方「自检与冒烟」。

### 中间迭代

已成功构建当前 Shell 时，可以直接运行开发输出：

```bash
"$HOME/.dotnet/dotnet.exe" run --project ./src/Momoka.Shell/Momoka.Shell.csproj -c Release --no-build
```

桌面快捷方式仍指向发布目录；此命令不构成最终交付。普通应用可能恢复保存的登录，播放授权仍按主规则执行。

### 约定基线

`AgreementsTests.cs` 对照同目录 `Agreements.txt` 检查内联字号和颜色、嵌套绑定、已有自动化句柄、开关及分析器哈希，实际结果写入 `artifacts/code-review/agreements-actual.txt`。

新增、改名、合并或退役项目时，先核对受影响调用者、脚本和文档，说明保留的覆盖，再只改对应基线行。旧快照并非禁止重构，新快照也不能不经复核整份覆盖。

### 分析器维护

发版使用仓库 `tools/analyzers` 的确定载荷，完整性由约定测试的哈希检查守卫。`Directory.Build.props` 的 `Condition=Exists` 会让缺载荷的构建继续，不能只看警告数。

下列命令只比较本机插件候选与仓库副本，不是发版必过项：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/refresh-analyzers.ps1 -Check
```

默认候选按文件写时间选择，不保证语义版本最新。找不到候选时脚本说明跳过并返回 0；这个 0 不证明载荷存在或有效。明确选择来源后，独立升级：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/refresh-analyzers.ps1
```

可用 `-SkillRoot <分析器目录>` 指定来源；复核新诊断、文件和哈希，逐行更新基线，再按主规则跑完整四道闸门。不要为了匹配本机旧插件降级。

## 发布与交付

需要自包含目录及 ZIP 时运行：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/publish.ps1
```

默认输出为当前工作树的 `artifacts/publish/win-x64`，版本来自 `Directory.Build.props`。发布采用单节点及与标准构建一致的 MSBuild 参数，再运行 `verify-publish.ps1` 检查载荷、框架 PRI 等完整性。

发布前确认目标应用已关闭；脚本发现目标进程仍运行时会在清理之前拒绝，不能擅自杀用户进程。默认发布会清理旧输出，**不会自动归档一份改动前的发布包**。需要回归对照时，事先另外保留完整产物并记录来源提交、工作区差异及产物哈希；上一份发布包可能已经包含本轮早先改动。

`-NoArchive` 只省去 ZIP，仍刷新可运行目录。`-SkipPublish` 只拿现有产物打包，不证明它来自当前源码。独立工作树的发布也不会刷新主目录或已有快捷方式；交付由一个会话整合、验证后完成。

每棵要发布的树都需要匹配的根目录 `libmpv-2.dll`（不入库）；着色器和原生依赖分别在 `assets/shaders`、`assets/mpv-runtime`，独占控件在 `assets/mpv-ui`，由项目复制。完整性检查不等于实际播放通过。

默认 ZIP 是自包含的非打包 WinUI 应用，目标机器不需预装 .NET Desktop Runtime 或 Windows App SDK。`-FrameworkDependent` 减小包体积，但需要目标机器预装运行时。WebView2 Runtime 仅用于服务器控制台；缺失时该页提供浏览器替代入口。需要 MSIX 时传 `-Msix`，签名与打包参数以脚本为准。

发布默认不改桌面。确需创建快捷方式时传 `-Shortcut`，或单独运行：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/shortcut.ps1
```

快捷方式指向发布目录的 `Momoka.exe`；`-Exe <路径>` 可明确指定其他构建，`-Remove` 删除快捷方式，不得用改指向来掩盖未完成的交付。

### 代码签名与 SmartScreen

交付件没有代码签名时，从网上下载它的人第一次双击会看到「Windows 已保护你的电脑 / 发布者未知」。三条事实决定了这事的做法，按微软现行文档核实（[Code signing options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)、[SmartScreen reputation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)）：

1. **SmartScreen 一般只评估带「来自互联网」标记（MOTW / `Zone.Identifier` 流）的文件**，「本地构建的 exe 被拦」先拿流列表核实，别照猜处理。但要留一手：2026-10-01 本机实测三轮，交付件全程无 MOTW 仍被拦——文档说的是一般行为，不是本机判定器的完整判据，别把「无标记」当「必然不拦」的证据。
2. **自签名证书没用。** 官方口径是自签名的 SmartScreen 行为**与不签名相同**：签名者不是受信任根，Windows 照样报「发布者未知」。拿本机自签证书签交付件只增加一层看起来安全的假象，唯一作用是本机 `signtool verify` 能过（MSIX 旁加载需要它），不解决提示。
3. **证书也不等于立刻免提示。** OV／EV 证书首个版本仍可能提示，信誉按同一个发布者身份随下载量累积；EV 自 2024 年起不再免检。真免提示只有两条路：CA 签发的证书（¥千元级/年，中国大陆个人走传统 CA；微软 Azure Artifact Signing 不对中国大陆个人开放）或上架 Microsoft Store（微软代签，但需开发者账号与审核）。换证书会让已有信誉清零，签名身份要一次定死。

本机消除下载件的提示用 `tools/unblock-momoka.ps1`：只摘 Momoka 自己那些文件的 MOTW，先清点后动手。

```bash
powershell -NoProfile -File tools/unblock-momoka.ps1           # 只看会动哪些
powershell -NoProfile -File tools/unblock-momoka.ps1 -Apply    # 真摘
```

两个坑写在脚本注释里，也值得在这里留一句：受限沙箱终端对工作区外的写入会被**静默忽略**，`Unblock-File` 会「成功退出但标记一个字节没少」，所以脚本不复用它的返回值判定成败，而是**读回流列表**；换普通 PowerShell 窗口重跑即可。另外 Inno Setup 写进 PE 的版本字符串是定长补空格的（`ProductName` 实际是 `"Momoka"` 加四十多个空格），按产品名认文件必须先 `Trim()`。

**给交付件签名**（本机自用或企业受管分发场景）用 `tools/sign-release.ps1`：

```bash
# 建证书并装进本机受信任存储，管理员终端只需一次
powershell -NoProfile -ExecutionPolicy Bypass -File tools/sign-release.ps1 -Setup
# 之后普通终端签名（文件或整个目录）
powershell -NoProfile -ExecutionPolicy Bypass -File tools/sign-release.ps1 -Path artifacts\publish\win-x64\Momoka.exe
# 看现状：证书、受信任存储、链能不能建起来
powershell -NoProfile -ExecutionPolicy Bypass -File tools/sign-release.ps1 -Status
```

signtool 从 NuGet 的 `microsoft.windows.sdk.buildtools` 里取（这台机器没有 Windows SDK）；签名默认带 DigiCert 时间戳。**两条代价说清**：① 自签证书只对本机有效——证书装进 `LocalMachine\Root` 之后，这台机器才把它当可信发布者，别人的机器上行为与不签名相同；② **签名会改交付件的字节**，`artifacts\publish\win-x64\Momoka.exe` 的 sha256 此后不再等于 `obj` 里那份重编产物，仓库原先"发布件与 obj 逐字节一致"的复核口径对**这个文件**不再适用，要按"已签名"解释。

签名不必然消掉提示。本机「双击本地构建的 exe 也被拦」一案（2026-10-01）的**真凶是目录上的低强制完整性标签**：`C:\Users\89400\Momoka` 曾带 `Mandatory Label\Low:(OI)(CI)(NW)`，全树继承，urlmon 查安全描述符时把低完整性本地文件判为 Internet 区——与 MOTW、签名、发布者商店、SmartScreen 各开关**全部无关**，改名甩不掉、显式盖 `ZoneId=0` 的 ADS 也压不住。**判别命令一条**：`icacls <路径> | findstr Mandatory`；**修复一条**：`icacls <目录> /setintegritylevel (OI)(CI)M`（继承自动传播，无需提权）。标签来源未查明，症状复发先查它。

SmartScreen 各层开关的事实（应急时用，均与本案根因无关）：用户层落点是 `HKCU/HKLM\...\Explorer\SmartScreenEnabled`（**值不存在 = 默认开启**；`-SetShellSmartScreen Off|On` 写/删它，不需管理员）；策略层硬开关 `HKLM\SOFTWARE\Policies\Microsoft\Windows\System\EnableSmartScreen`（0 = 对所有用户关闭）；`AppHost\EnableWebContentEvaluation` 两处与 `Safer\CodeIdentifiers` 发布者登记对提示**无效**（实测），别再走。

**对照方法**：用 `ShellExecute` 起进程比 `Start-Process` 更接近"双击"；`cmd start` 那条路**绕过**检查，不能用来判断；`ShellExecute` **返回 ≠ 放行**（实测返回了进程没起），判定看进程在不在。追踪判定来源用 Procmon 对比「Internet 判定」与「MyComputer 判定」两个进程的操作差集——本案唯一分歧点是 `QuerySecurityFile`，由此锁死完整性标签。

关掉 SmartScreen 类开关是**关防护**，必须用户同意；本案结束后各开关已全部恢复出厂。
## 视频输出的隔离验证边界

`VideoOutputTests` 覆盖规范选项拼法、HDR 成套临时菜单、四种整数亮度（与小数对比度分开）、元数据组合、设置快照和链前置条件；`ShaderTransactionTests` 覆盖切链拒绝/异常、缺默认值、缺旧值、回滚失败、代次变化与并发。它们是 Core 规则/假后端，不证明 shader 编译或 HDR 显示正确。

实际控件检查需独立宿主：只创建临时默认设置，不走普通 App 启动/真实账号；需要会话的夹具必须拒绝 HTTP 且禁止起播。`--show-settings` 仍是普通路径，不能当离线探针。当前未新增产品级视频探针开关。

原生核对分两种：无媒体句柄读取选项/default/profile/list 并运行切链服务；本地合成视频用 `vo-passes`、渲染日志和截图验证真正执行的算法。文件列表格式化文本会丢分号转义，回滚使用无损节点/JSON列表；单个空路径与空列表都没有 shader，不能把它当属性不可读。固定全屏选档和实际窗口门控是不同尺寸，pass缺席可能是门控，不一律是编译失败。

普通闸门4、真实HDR显示器、杜比素材、外部真实mpv或uosc端到端仍分别验收；不以无声/无窗口采样替代。

## 命令行开关

源码入口为 `src/Momoka.Shell/Program.cs`，参数解析在 Core 的 `StartupArgs`；`AgreementsTests` 的 `switch` 小节提醒同步本说明。

- **导航与展示**：`--show-detail`、`--show-episode`、`--show-library`、`--show-settings <分类>`（默认“界面”）、`--show-menu`（首页第一张卡的更多菜单）、`--show-picker`（详情页那一颗下拉弹开：字幕优先，没有字幕轨的片子退到音频）、`--show-cover`（配详情页）、`--scroll-end` / `--scroll-half`（配详情类开关）、`--theme <id>`、`--maximized`、`--screen <n>`。
- **不播放的状态展示**：`--show-osd [pinned|paused|playing]` 固定浮层状态；`--hide-cursor` 保持播放页心跳，观察自动隐藏。
- **隔离本地探针**：`--probe-cursor [<本地视频绝对路径>]`、`--probe-player-motion [<本地视频绝对路径>]`、`--probe-composition [<本地视频绝对路径>]`。
- **字幕设置离线探针**：`--probe-subtitles [inspect]`，只允许另带 `--screen <n>`、`--theme <id>`。启动前隔离数据、不读取真实设置、不创建登录和播放服务，验证颜色输入与异步回填、主次字幕规则的界面接线、删除确认、字幕操作互斥与响应中断后的刷新、保存失败/重试、恢复后推送和字幕预览。截图和报告写入 `%LOCALAPPDATA%/Momoka/logs/subtitle-probe-<时间>-<进程>/logs/`。默认跑完退出，`inspect` 将假字幕确认面板留屏供手工/UIA 检查（最多八分钟）；退出码 0 表示运行断言通过，渲染 PNG 不替代真实屏幕视觉验收。与普通自检共用桌面互斥，须串行运行。
- **普通 Shell 离线探针**：`--probe-shell [inspect]`，只允许另带 `--screen <n>`、`--theme <id>`。进入独立目录后只创建假身份、假传输和临时设置，不读取真实设置、不创建播放服务，外部播放和真实网络均被拒绝。检查分页失败/取消/恢复、搜索返回、切季交错、切服与目录重试、通知离页、播放返回主页后的延迟刷新不补播入场、封面操作及对话框接线；主页返回检查保存两种窗口宽度的返回及刷新后渲染截图。报告为 `%LOCALAPPDATA%/Momoka/logs/shell-probe-<时间>-<进程>/logs/shell-probe.json`；默认执行后退出，`inspect` 留下本地假图片界面供实际操作（最多八分钟）。与测试及普通自检共用互斥，须串行。该探针不覆盖真实服务器写入、播放、WebView2 或完整普通自检；退出码0只代表其明确登记的运行断言通过。
- **自检**：`--self-check`；可配 `--dump-ui`、`--screen`、`--theme`，以及 `--self-check-data <全新目录>` 指定隔离数据落点。数据目录参数不能用于普通启动。
- **真实起播**：`--play`，须取得真实服务器播放授权，不能与自检混用。

`--show-menu`、`--show-picker`、`--show-osd`、`--hide-cursor` 各自单独使用，互不混用、不与自检混用。菜单/浮层会挡住换页，自检结束会退出，固定 OSD 又与自动收起相反；各探针也单独运行。`--show-picker` 可选配 `--show-detail` / `--show-episode`（已经在详情页上就不再导航一遍，单独用时自己走到第一张详情页）；它会**等那颗下拉的列表站好**再弹（剧页/电影页上那份列表挂在播放落点那一次请求上，比页面晚好几拍），最多等 5 秒，到点还没来就记一句「这一页上没有可弹的下拉」。

`--theme` 同时接受 `--theme=midnight`，不写用户设置；未知主题回落默认。主题清单从 `UiThemes.cs` 获取，已删除的 `daylight` 不代表一个可测试的浅色主题。以下为**主窗口**主题截图示例：先确认目标应用未运行，且本次允许普通启动读取保存的账号；它不是离线探针。

## 音频输出离线验证

先运行采集器的安全/失败夹具，再用当前树的随包内核做零信号采集。原生采集默认读取工作树根目录的 `libmpv-2.dll`；它不入库，干净检出须另行提供与当前应用匹配的x64副本，或用 `--dll <已核实的绝对路径>` 指定。依赖布局见[发布与交付](#发布与交付)和[原生运行时说明](../assets/mpv-runtime/README.md#为什么它必须跟着发)；即使禁视频，静态依赖 `vulkan-1.dll` 也不能缺。

先确认实际Python解释器为 `win-amd64 64`，再用同一解释器执行。缺少匹配DLL或现有Python并非x64时，仍可用现有Python运行不加载原生库的夹具，原生采集应记为未覆盖：

```bash
py -c "import struct, sysconfig; print(sysconfig.get_platform(), struct.calcsize('P') * 8)"
py .claude/skills/momoka-audio-output/scripts/test-probe-audio-native.py
py .claude/skills/momoka-audio-output/scripts/probe-audio-native.py --out work/audio-native-current.json
```

规则与假后端回归见 `AudioOutputTests`、`PlaybackTests`、`SettingsTests` 和 `InlineSwitchTests`。真实设置控件仍需使用隔离宿主或 `--probe-subtitles inspect` 验输入、失焦、清空占位与保存失败；核对隔离设置文件，不以UIA命令接受代替落盘。音量的默认100须与 `VolumeKnown` 真读数区分，独占无播放页时的保存时钟也需独立覆盖。加载期相对音量分支的测试缺口，以及 `inspect` 的空设备目录和字幕断言边界，见[音频技能的五层验证](../.claude/skills/momoka-audio-output/SKILL.md#五层验证)。

## 自检与冒烟

`--self-check` 使用诊断窗口构建、布局并绘制页面与播放器合成状态，不加载影片。检查范围包括窗口几何、标题栏命中、浮层显隐、主题资源、设置模板、列表导航、详情页、字幕字体（设置页那一张，播放页那颗搜索框 2026-09-27 已退役）以及着色器档位；当前检查名以源码和 `selfcheck-baseline.txt` 为准，不在文档维护检查数量副本。

普通自检可能复制保存的账号设置并登录真实服务器，读取真实媒体库。它不是离线探针；缺账号、缺素材或无法走到某项检查时的“信息/跳过”也不等于通过。

自检在全新目录使用设置副本、日志、缓存和 WebView 数据，不执行生产目录迁移，不写回真实设置或备份。副本按非最大化运行，生产应用的窗口偏好不变。同一用户的自检用互斥防止跨树同时操作桌面；其他 UI 验证也须自行串行安排。

`selfcheck-diff.ps1` 把隔离目录放在当前树 `artifacts/selfcheck/<运行标识>`，报告位于其中 `logs/selfcheck-shell.txt`，控制台输出确切路径。直接启动自检时会另建唯一运行目录；可通过 `--self-check-data` 指定尚不存在的本地目录。目录中可能保留 DPAPI 设置副本和真实库读数，**不要提交或公开上传**。

```bash
./artifacts/publish/win-x64/Momoka.exe --self-check --dump-ui
```

`--dump-ui` 在同一运行目录的 `logs` 中输出最后一页的 `selfcheck-shell.png` 与 `selfcheck-shell-tree.txt`。首页媒体库卡片实现后，还输出 `selfcheck-library-card-Normal.png`、`selfcheck-library-card-PointerOver.png`、`selfcheck-library-card-Pressed.png`：直接切换外层按钮模板的常态、悬停和按压状态，拍完恢复，不移动鼠标、不触发点击或播放。`卡片悬浮按钮` 检查同时读取外层按钮三态的实际背景，防止名称后面的白底回归。PNG 不合成 Mica，也不包含系统光标，不能替代真实屏幕截图或光标证据。

### 逐行比报告：每次都会变的行

自检基线比较**检查名与状态**，不比较详情中的每个数字。时间、窗口/光标句柄、线程号、计时、服务器条目与诊断日志数量等读数可能变化，但仍需结合对应断言理解：不能仅因数字曾变化就把失败划掉。

已有报告可单独比较：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/selfcheck-diff.ps1 -Log work/log.txt
```

确认新增或合法重构的检查后才更新基线：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/selfcheck-diff.ps1 -UpdateBaseline
```

基线只存状态和检查名，重复的展示项由其所属检查覆盖；任何失败都要保留为红，不能被同名的通过行覆盖。缺失或不完整的报告、未验证来源的旧报告，不构成本次验收。更新基线前按主规则逐项复核，已知旧失败也不能通过更新基线豁免。

做版本对照时保留两份报告并核实产物确实位于改动前后，同时记录账号、库数据、窗口状态等运行条件。相同症状曾出现不等于本轮没有加重，两个文件哈希不同也不证明时间先后。具体判断方法见验证技能。

`smoke.ps1` 只启动应用、等待并报告进程是否仍活着；存活不是播放验收：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File smoke.ps1 -Release
```

设置左栏按 Momoka（本机偏好、服务器连接、诊断）和 EmbyServer（原生控制台、用户、通知、网页控制台）分组。

`--probe-shell` 同时验证分组导航、三种窗口尺寸、设备和活动列表、播放进度、未登录状态及离页取消，保存 `server-dashboard-1240.png`、`server-dashboard-1018.png` 和 `server-dashboard-760.png`；这些截图使用离线夹具，不证明真实服务器响应。
管理菜单探针会实际打开菜单、名称编辑、信息和电源确认对话框并截图，只通过假确认和假传输验证提交路径，同时检查取消、权限不足和切服竞态。

## 本机工具与故障排查

- **SDK**：用用户级 `.dotnet/dotnet.exe` 按 `global.json` 核实；PATH 曾有旧 SDK，不以旧版本判断环境可用。单节点要求来自本机 workload 解析器曾间歇性无输出失败，不因此断言每次失败都是解析器。
- **Python**：用 `py`；PATH 的 `python`/`python3` 曾被 Store 存根遮蔽，静默退出不证明执行成功，版本以当场查询为准。
- **PowerShell**：源码使用 UTF-8 BOM、LF，兼容 Windows PowerShell 中文解析。终端若错误解码输出，可对该进程设置 UTF-8 输出编码；不要靠重写源码来修终端显示。
- **读取与转义**：优先专用读取/搜索工具；本机曾有遮蔽系统命令的 shell 函数，异常行号先核实实际命令。复杂内联脚本优先改为文件，检查实际命中而非只看退出码。
- **构建环境变量**：`tools/build.cmd` 是旧沙箱缺少 Windows 环境变量时的兼容入口，不是默认必需步骤；只有确认该问题才使用。其 `test` 入口也会先编译，不能用作跳过编译的捷径。
