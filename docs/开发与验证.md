# 开发与验证

本文保存命令、操作方法和有适用条件的排障经验；当前规则与验证触发条件见 [CLAUDE.md](../CLAUDE.md)，在途工作及历史证据见 [PROGRESS.md](../PROGRESS.md)。版本、参数和检查能力以源码与脚本为准，不在这里另立授权或验收标准。

## 架构

解决方案为 `EmbyNian.sln`：

- `src/EmbyNian.Core`：Emby 访问、设置与凭据保险箱、mpv 配置，以及内置 `LibMpvBackend` 和外部 `MpvProcessBackend`。不引用桌面 UI；当前无 NuGet 依赖，这是轻量选择，不是测试框架限制。
- `src/EmbyNian.Shell`：WinUI 外壳，Windows App SDK 按需引用子包，具体版本以 csproj 为准。
- `tests/EmbyNian.Tests`：当前只引用 Core 的离线控制台测试宿主，`dotnet run` 是 runner。

旧 WinForms 外壳已退出工作树；需要查迁移历史时用 Git 历史，不恢复旧目录作为新增实现模板。架构与专项操作见 `.claude/skills/`。

## 构建与运行

### 标准命令

在**当前工作树根目录**运行。使用 `$HOME/.dotnet/dotnet.exe`，先按 `global.json` 核实 SDK；不要跳回另一棵树，也不要让 IDE 或 `dotnet run` 隐式触发不同参数的构建。各类任务需要哪些闸门、如何判定交付，统一见 [主规则](../CLAUDE.md#四道闸门与日常交付)。

新工作树缺少还原结果或包版本变化时先还原：

```bash
"$HOME/.dotnet/dotnet.exe" restore ./EmbyNian.sln --disable-parallel -m:1 -p:BuildInParallel=false
```

**闸门 1：完整构建与空白检查。**

```bash
"$HOME/.dotnet/dotnet.exe" build ./EmbyNian.sln -c Release --no-restore -m:1 -p:BuildInParallel=false -p:UseSharedCompilation=false -p:MSBuildNodeReuse=false
```

```bash
"$HOME/.dotnet/dotnet.exe" format whitespace ./EmbyNian.sln --verify-no-changes --no-restore
```

`format whitespace` 不检查所有脚本的编码和语法；改 PowerShell 脚本或完整验收时另外运行：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-scripts.ps1
```

该脚本检查当前工作树受版本控制及未忽略的新 `.ps1`：UTF-8 BOM、LF、末尾换行和 PowerShell 语法。它不执行脚本，不证明脚本的运行行为正确；`-Path <文件>` 可检查指定文件。

维护脚本的离线回归使用隔离夹具，不启动产品、不发布到实际交付目录，也不改仓库的分析器载荷：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/test-maintenance.ps1
```

**闸门 2：先编译当前测试，再运行。** 没有可复用的当前完整构建时先执行：

```bash
"$HOME/.dotnet/dotnet.exe" build ./tests/EmbyNian.Tests/EmbyNian.Tests.csproj -c Release --no-restore -m:1 -p:BuildInParallel=false -p:UseSharedCompilation=false -p:MSBuildNodeReuse=false
```

前一步成功后执行：

```bash
"$HOME/.dotnet/dotnet.exe" run --project ./tests/EmbyNian.Tests/EmbyNian.Tests.csproj -c Release --no-build
```

`-c Release` 只能选输出目录，不能证明输出是新的；发布 Shell 也不会刷新测试程序集。

**闸门 3：刷新实际交付目录。**

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/publish.ps1 -NoArchive
```

**闸门 4：自检及基线比较。**

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/selfcheck-diff.ps1
```

自检会操作窗口，并可能使用保存的账号读库，不是离线测试。报告位置与隔离机制见下方「自检与冒烟」。

### 中间迭代

已成功构建当前 Shell 时，可以直接运行开发输出：

```bash
"$HOME/.dotnet/dotnet.exe" run --project ./src/EmbyNian.Shell/EmbyNian.Shell.csproj -c Release --no-build
```

桌面快捷方式仍指向发布目录；此命令不构成最终交付。普通应用可能恢复保存的登录，播放授权仍按主规则执行。

### 约定基线

`AgreementsTests.cs` 对照同目录 `Agreements.txt` 检查内联字号和颜色、嵌套绑定、已有自动化句柄、开关及分析器哈希，实际结果写入 `artifacts/code-review/agreements-actual.txt`。

新增、改名、合并或退役项目时，先核对受影响调用者、脚本和文档，说明保留的覆盖，再只改对应基线行。旧快照并非禁止重构，新快照也不能不经复核整份覆盖。

### 分析器维护

发版使用仓库 `tools/analyzers` 的确定载荷，完整性由约定测试的哈希检查守卫。`Directory.Build.props` 的 `Condition=Exists` 会让缺载荷的构建继续，不能只看警告数。

下列命令只比较本机插件候选与仓库副本，不是发版必过项：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/refresh-analyzers.ps1 -Check
```

默认候选按文件写时间选择，不保证语义版本最新。找不到候选时脚本说明跳过并返回 0；这个 0 不证明载荷存在或有效。明确选择来源后，独立升级：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/refresh-analyzers.ps1
```

可用 `-SkillRoot <分析器目录>` 指定来源；复核新诊断、文件和哈希，逐行更新基线，再按主规则跑完整四道闸门。不要为了匹配本机旧插件降级。

## 发布与交付

需要自包含目录及 ZIP 时运行：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/publish.ps1
```

默认输出为当前工作树的 `artifacts/publish/win-x64`，版本来自 `Directory.Build.props`。发布采用单节点及与标准构建一致的 MSBuild 参数，再运行 `verify-publish.ps1` 检查载荷、框架 PRI 等完整性。

发布前确认目标应用已关闭；脚本发现目标进程仍运行时会在清理之前拒绝，不能擅自杀用户进程。默认发布会清理旧输出，**不会自动归档一份改动前的发布包**。需要回归对照时，事先另外保留完整产物并记录来源提交、工作区差异及产物哈希；上一份发布包可能已经包含本轮早先改动。

`-NoArchive` 只省去 ZIP，仍刷新可运行目录。`-SkipPublish` 只拿现有产物打包，不证明它来自当前源码。独立工作树的发布也不会刷新主目录或已有快捷方式；交付由一个会话整合、验证后完成。

每棵要发布的树都需要匹配的根目录 `libmpv-2.dll`（不入库）；着色器和原生依赖分别在 `assets/shaders`、`assets/mpv-runtime`，独占控件在 `assets/mpv-ui`，由项目复制。完整性检查不等于实际播放通过。

默认 ZIP 是自包含的非打包 WinUI 应用，目标机器不需预装 .NET Desktop Runtime 或 Windows App SDK。`-FrameworkDependent` 减小包体积，但需要目标机器预装运行时。WebView2 Runtime 仅用于服务器控制台；缺失时该页提供浏览器替代入口。需要 MSIX 时传 `-Msix`，签名与打包参数以脚本为准。

发布默认不改桌面。确需创建快捷方式时传 `-Shortcut`，或单独运行：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/shortcut.ps1
```

快捷方式指向发布目录的 `EmbyNian.exe`；`-Exe <路径>` 可明确指定其他构建，`-Remove` 删除快捷方式，不得用改指向来掩盖未完成的交付。

## 命令行开关

源码入口为 `src/EmbyNian.Shell/Program.cs`，参数解析在 Core 的 `StartupArgs`；`AgreementsTests` 的 `switch` 小节提醒同步本说明。

- **导航与展示**：`--show-detail`、`--show-episode`、`--show-library`、`--show-settings <分类>`（默认“界面”）、`--show-menu`（首页第一张卡的更多菜单）、`--show-cover`（配详情页）、`--scroll-end` / `--scroll-half`（配详情类开关）、`--theme <id>`、`--maximized`、`--screen <n>`。
- **不播放的状态展示**：`--show-osd [pinned|paused|playing]` 固定浮层状态；`--hide-cursor` 保持播放页心跳，观察自动隐藏。
- **隔离本地探针**：`--probe-cursor [<本地视频绝对路径>]`、`--probe-player-motion [<本地视频绝对路径>]`、`--probe-composition [<本地视频绝对路径>]`。
- **自检**：`--self-check`；可配 `--dump-ui`、`--screen`、`--theme`，以及 `--self-check-data <全新目录>` 指定隔离数据落点。数据目录参数不能用于普通启动。
- **真实起播**：`--play`，须取得真实服务器播放授权，不能与自检混用。

`--show-menu`、`--show-osd`、`--hide-cursor` 各自单独使用，互不混用、不与自检混用。菜单/浮层会挡住换页，自检结束会退出，固定 OSD 又与自动收起相反；各探针也单独运行。

`--theme` 同时接受 `--theme=midnight`，不写用户设置；未知主题回落默认。主题清单从 `UiThemes.cs` 获取，已删除的 `daylight` 不代表一个可测试的浅色主题。主题截图示例：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/shot.ps1 -Exe artifacts/publish/win-x64/EmbyNian.exe -Out work/midnight.png -ExeArgs "--theme midnight --show-settings" -WindowTitle 设置
```

## 隔离光标回归

`--probe-cursor` 在登录、单实例激活和用户设置加载之前进入独立目录，使用正式播放页和其计时器，不启动 Emby 播放、不上报记录：

```bash
./artifacts/publish/win-x64/EmbyNian.exe --probe-cursor --screen 1
```

可选的本地视频路径必须为绝对路径，拒绝 URL、网络盘和重解析路径，并禁止素材引用外部文件或网络协议。同族还有 `--probe-player-motion` 和 `--probe-composition`；**三条都固定走集成管线，不覆盖独占/uosc 或外部 mpv**。

光标探针会暂时移动鼠标、创建窗口并切换全屏；结束时恢复输入连接、光标和位置。不能取得真实输入或指针离开窗口时，属于失败或覆盖缺口，内部状态不能代替系统可见光标。结果在 `%LOCALAPPDATA%/EmbyNian/logs/cursor-probe-<时间>-<进程>/logs/cursor-probe.txt`。

2026-09-22 已停止普通自检中依赖真鼠标静止的三关：`藏鼠标真的到了系统`、`鼠标真等两秒就藏`、`藏匿期净位移走不够一百像素不醒`。不要重新登记或把其缺席当回归；独立 `--probe-cursor` 与其他正常光标断言仍保留。

## 隔离缩放像素回归

`--probe-player-motion` 使用固定红、绿、黄、蓝、品红、青六条彩条，运动区只放顶部；普通影片不满足取色判据。可在当前树生成本地夹具，命令拒绝覆盖同名文件：

```bash
ffmpeg -hide_banner -loglevel error -f lavfi -i "color=c=red:s=1280x720:r=30:d=45" -f lavfi -i "testsrc2=s=1280x72:r=30:d=45" -filter_complex "[0:v]drawbox=x=214:y=0:w=213:h=720:color=lime:t=fill,drawbox=x=427:y=0:w=213:h=720:color=yellow:t=fill,drawbox=x=640:y=0:w=213:h=720:color=blue:t=fill,drawbox=x=853:y=0:w=213:h=720:color=magenta:t=fill,drawbox=x=1066:y=0:w=214:h=720:color=cyan:t=fill[bars];[bars][1:v]overlay=x=0:y=0:shortest=1[out]" -map '[out]' -an -c:v libx264 -preset fast -crf 18 -pix_fmt yuv420p -n work/resize-bars-fixture.mp4
```

```bash
ffmpeg -hide_banner -loglevel error -i work/resize-bars-fixture.mp4 -frames:v 1 -n work/resize-bars-fixture.png
```

```bash
./artifacts/publish/win-x64/EmbyNian.exe --probe-player-motion "$(pwd -W)/work/resize-bars-fixture.mp4" --screen 2
```

单屏用 `--screen 1`。探针通过原生拖边消息走正式宽高比约束，不移动真鼠标；像素检查临时置顶，结束后恢复。覆盖缓冲、视频推进、最终尺寸、保留帧收回及中断收尾等行为；取色从一次屏幕捕获完成，窗口被遮挡或移出屏幕不能算通过。快速反向拖边仍需外部连续捕获检查中间帧。

报告位于 `%LOCALAPPDATA%/EmbyNian/logs/player-motion-probe-<时间>-<进程>/logs/player-motion-probe.txt`。非阻断诊断单独读，退出码 0 不代表每条诊断都通过。探针暂停过播放页轮询，验证住在 `OnTick` 中的规则前须确认该规则实际执行，详见验证技能。

## 自检与冒烟

`--self-check` 使用诊断窗口构建、布局并绘制页面与播放器合成状态，不加载影片。检查范围包括窗口几何、标题栏命中、浮层显隐、主题资源、设置模板、列表导航、详情页、字幕字体以及着色器档位；当前检查名以源码和 `selfcheck-baseline.txt` 为准，不在文档维护检查数量副本。

普通自检可能复制保存的账号设置并登录真实服务器，读取真实媒体库。它不是离线探针；缺账号、缺素材或无法走到某项检查时的“信息/跳过”也不等于通过。

自检在全新目录使用设置副本、日志、缓存和 WebView 数据，不执行生产目录迁移，不写回真实设置或备份。副本按非最大化运行，生产应用的窗口偏好不变。同一用户的自检用互斥防止跨树同时操作桌面；其他 UI 验证也须自行串行安排。

`selfcheck-diff.ps1` 把隔离目录放在当前树 `artifacts/selfcheck/<运行标识>`，报告位于其中 `logs/selfcheck-shell.txt`，控制台输出确切路径。直接启动自检时会另建唯一运行目录；可通过 `--self-check-data` 指定尚不存在的本地目录。目录中可能保留 DPAPI 设置副本和真实库读数，**不要提交或公开上传**。

```bash
./artifacts/publish/win-x64/EmbyNian.exe --self-check --dump-ui
```

`--dump-ui` 在同一运行目录的 `logs` 中输出 `selfcheck-shell.png` 与 `selfcheck-shell-tree.txt`，仅保留最后一页。PNG 不合成 Mica，也不包含系统光标，不能替代真实屏幕截图或光标证据。

### 逐行比报告：每次都会变的行

自检基线比较**检查名与状态**，不比较详情中的每个数字。时间、窗口/光标句柄、线程号、计时、服务器条目与诊断日志数量等读数可能变化，但仍需结合对应断言理解：不能仅因数字曾变化就把失败划掉。

已有报告可单独比较：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/selfcheck-diff.ps1 -Log work/log.txt
```

确认新增或合法重构的检查后才更新基线：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/selfcheck-diff.ps1 -UpdateBaseline
```

基线只存状态和检查名，重复的展示项由其所属检查覆盖；任何失败都要保留为红，不能被同名的通过行覆盖。缺失或不完整的报告、未验证来源的旧报告，不构成本次验收。更新基线前按主规则逐项复核，已知旧失败也不能通过更新基线豁免。

做版本对照时保留两份报告并核实产物确实位于改动前后，同时记录账号、库数据、窗口状态等运行条件。相同症状曾出现不等于本轮没有加重，两个文件哈希不同也不证明时间先后。具体判断方法见验证技能。

`smoke.ps1` 只启动应用、等待并报告进程是否仍活着；存活不是播放验收：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File smoke.ps1 -Release
```

## 数据与路径

普通应用数据位于 `%LOCALAPPDATA%/EmbyNian`：`settings.json`/`settings.backup.json`、`logs`、`cache/images`、`screenshots`、`webview2`。正常模式对损坏设置执行隔离与恢复；自检不能借此修改生产文件，只能在自己的副本中工作。

外部 mpv 路径在「设置 → 播放器」配置；内置后端使用随程序分发的原生库与资源。两个后端都不读取用户的 `mpv.conf` / `input.conf`。

## 本机工具与故障排查

- **SDK**：用用户级 `.dotnet/dotnet.exe` 按 `global.json` 核实；PATH 曾有旧 SDK，不以旧版本判断环境可用。单节点要求来自本机 workload 解析器曾间歇性无输出失败，不因此断言每次失败都是解析器。
- **Python**：用 `py`；PATH 的 `python`/`python3` 曾被 Store 存根遮蔽，静默退出不证明执行成功，版本以当场查询为准。
- **PowerShell**：源码使用 UTF-8 BOM、LF，兼容 Windows PowerShell 中文解析。终端若错误解码输出，可对该进程设置 UTF-8 输出编码；不要靠重写源码来修终端显示。
- **读取与转义**：优先专用读取/搜索工具；本机曾有遮蔽系统命令的 shell 函数，异常行号先核实实际命令。复杂内联脚本优先改为文件，检查实际命中而非只看退出码。
- **构建环境变量**：`tools/build.cmd` 是旧沙箱缺少 Windows 环境变量时的兼容入口，不是默认必需步骤；只有确认该问题才使用。其 `test` 入口也会先编译，不能用作跳过编译的捷径。
- **WMC9999**：曾由 WinUI 标记编译缓存引起，也曾报过期源码位置。保留输出后可原样重试一次；持续失败正常定位，不能凭错误码断言不是 XAML 问题或盲目清空输出。
- **PRI**：发布件缺 `Microsoft.UI.Xaml/Themes/themeresources.xaml` 时检查 Shell 的 `AddWindowsAppSdkFrameworkPriToPayload` 与发布校验；框架资源缺失不靠“再发布一次”解决。升级包后重新核实合并载荷。
- **截图与指针**：`tools/shot.ps1` 捕获真实屏幕，`--dump-ui` 不合成 Mica；普通 GDI/UIA 截图不含鼠标。光标使用 `cursor-watch.ps1` 的读数及叠加图，机制、授权和失败证据见验证技能；权限拒绝不能换工具绕过。
