# EmbyServer 用户管理

入口：设置 → EmbyServer → 用户，或 `--show-settings 用户`。以 Emby Server **4.10.0.40** 自带网页端 `users/*tab.js`、`users/usernew.js`、`settings/userpasswordcontroller.js` 及服务器 OpenAPI 为协议参考。

| 页面或操作 | 实际行为 |
| --- | --- |
| 用户列表 | 完整分页读取用户、头像、账号状态和最近活动；搜索、启用/禁用/管理员筛选、名称/活动/创建时间排序 |
| 新建用户 | 名称、管理员权限、媒体库和频道访问；可复制服务器提供的用户权限、设置、观看记录等数据选项 |
| 资料 | 改名、Emby Connect 关联/解绑、验证提供程序、远程访问、管理权限、播放/转码/下载/字幕/共享/直播权限、动态功能权限、并发流和码率限制、媒体删除权限、登录隐藏与禁用 |
| 访问 | 媒体库、子目录、频道、设备；采用 GUID/ReportedDeviceId 等服务器标识，保留未展示的权限项 |
| 家长控制 | 服务器提供的分级、未分级内容类型、包含/排除标签、分级与标签的全部/任意组合、每周访问时段 |
| 密码 | 设置或移除普通用户密码、管理员必填密码、四位个人 PIN 的设置与清除 |
| 用户操作 | 上传/移除头像、复制用户数据、带确认的删除；“编辑此用户的其他偏好”打开已登录的 Emby 原始偏好页面，并提供返回用户入口 |

资料、访问和家长控制共用一份编辑草稿，点击“保存用户设置”一起保存；密码、PIN 和头像分别提交。服务器端限制仍然有效，包括 Emby Premiere 功能授权；界面不绕过这些限制。

## 写入约定

- 用户和权限文档保留原始 JSON。保存前重新读取，只合并相对于打开页面时实际修改的字段，保留未知字段及其他客户端对无关字段的修改。
- 复制到现有用户的协议为 `POST Users/{来源用户}/CopyData`，正文使用 `ToUserIds` 和 `CopyOptions`；新建时的复制使用 `CopyFromUserId` 和 `UserCopyOptions`，两套参数不能混用。
- 用户头像上传遵循网页端的 Base64 正文约定，不能直接套用条目封面的原始字节上传接口。
- 新建成功但初始权限保存失败时，保留新用户身份并提供重试，避免再次创建账号。其他分步保存失败明确报错，不声称整个操作已经完成。
- 固定登录身份，离页取消；每次继续提交前核对身份。没有管理员权限时不能管理用户。删除默认取消，头像移除和复制覆盖也需确认。
- 凭据走现有请求头，不进入 URL；密码和 PIN 不写日志。

## 验证

`UserManagementTests` 覆盖接口方向、正文、分页完整性、未知字段和并发修改保留、密码/PIN/时段验证及反代路径。

`--probe-shell` 中的三个用户管理检查使用假传输，实际构建 WinUI 页面并验证列表、筛选、页签、输入绑定、保存回读、创建后的重试、复制、头像、删除确认、切服和离页。截图命名为 `server-users-*.png`。假传输结果不能当作真实服务器写入的证明；真实账号的创建、删除及权限改动仍需相应授权。
